QQ负载监控 v1.24

GIF专项处理测试版 · versionCode 25 · 2026-10-02

这次能处理什么

针对日志中反复短时执行的 com.tencent.libra.extension.gif.RenderTask.run，沿用当前负载规则定位对应的 GIF 对象，通过其公开 GifDrawable.stop() 接口停止播放，并拦截该对象后续的启动及渲染。即使上一帧任务已经返回，只要同一采样窗口内的执行证据和对象仍有效，也可以处理。

处理后的 GIF 会停在当前画面。QQ 进程与线程池工作线程保留，其他 GIF 对象可继续运行。该规则不能证明线程泄露，也不支持任意原生线程的强制终结。

触发口径

项目规则
监控对象与核心仅 QQ 同 UID 的进程；CPU0—7 可选，按所选核心的实际 CPU 时间合计，单核满载100%。
阈值与时长严格超过设置阈值，并达到设置的连续超限时长。阈值默认200%，持续0—3600秒可设；0秒在首轮有效超限尝试处理。
前后台前台与后台共用阈值和持续时长。无法确认前后台、采样过期或不完整时暂停处理。
GIF归属按真实TID/Java线程映射匹配完整窗口的RenderTask业务执行；已观测GIF业务CPU至少占目标线程全核CPU的50%；再扣除该线程全部未选核心CPU，剩余的GIF贡献保守下限必须达到所选核心线程负载的50%。这只用于业务归属判断，超限仍按所选核心计算。
调用前复核检查PID/TID启动身份、UID、采样时效、配置和GIF公开接口；不按线程名称猜任务，不取消已经换成其他业务的Future。
边界单次最多处理3个有证据的GIF对象；每进程最多保留32个暂停对象。同一未成功线程身份沿用10秒重试间隔。

连续超限时长按有效采样窗口累计。例如采样2秒、要求5秒，通常在累计达到6秒的有效采样处理。回落、无效、长间断、关闭或配置变化会重新计时。日志的执行观察有界且仅保留最近10秒；没有足够证据的长采样窗口不会猜测GIF归属。

开关与恢复

  1. 设置页新增 GIF专项处理：开启 / 关闭，默认开启。点击切换后保存设置，现有阈值、持续时长和采样间隔仍可自行调整。
  2. 处理页新增 恢复已暂停 GIF，向QQ各进程发出恢复请求，表格等待目标的实际回执。
  3. 关闭监控、关闭GIF专项或更改监控配置时，自动解除已有暂停。QQ重启后暂停记录清空。负载回落本身不会自动恢复，避免反复停止和播放。

恢复只主动启动仍有效、可见且当前渲染已返回的对象。不可见、已释放或渲染尚未返回的对象只解除拦截，不主动重播；该状态在详情中列明。

表格保留完整线程/PID/TID、QQ合计与线程自身负载、核心/当时阈值、前后台/时长、业务执行证据及对象处理结果。只有确认暂停后的完整有效采样窗口，才追加“复采QQ合计”。复采反映整体QQ负载，下降本身不能单独证明因果。

处理状态清单仍只保留最近100条，不增加清单导出。原监控日志新增 GIF_RULE 和 GIF_CHECK 生命周期/复采诊断，沿用明细页“导出日志到下载目录”，路径为 Download/QQWatchdog。
