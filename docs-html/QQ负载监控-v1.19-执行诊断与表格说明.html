处理表格现在显示什么

默认可见含义
时间、线程名、PID/TID有准确 Java 映射时显示完整线程名；否则保留内核线程名。长名字自动换行。
QQ合计、线程自身两项均按当时所选核心计算，避免把 QQ 合计负载误当成单个线程负载。
前后台、所选核心、当时阈值历史行保留触发时的设置，之后改阈值不改变旧记录。
实际状态与具体原因显示等待、任务变化、无法处理、仍在运行或已观察到返回等实际结果。
最近执行摘要显示最近业务方法、次数、CPU耗时、调度类型。标明全部核心参考，不能作为所选核心的处理归属证明。

点击一条记录，展开查看任务类、调度周期、入口栈，以及处理失败代码、任务窗口关系和诊断时刻的调用栈。没有映射、未覆盖、限频或截断会说明。最近100条仅保留于当前 QQ 会话，处理清单不导出。

新增 EXEC 执行证据

[DIAG] 继续记录处理失败原因；新增 [EXEC] 记录任务实例编号、业务类与 run/call 方法、调度类型与周期、窗口/近10秒/累计次数、任务入口及业务方法 CPU 耗时、执行入口栈。

固定频率、固定延迟和一次性调度从公开调度接口记录参数，并兼容可读取的平台字段。执行入口与业务方法次数分开：一次取消后的空入口不等于业务执行一次。正在执行的任务也显示已捕获的入口信息，CPU耗时等返回后统计。

窗口统计只包含完整落在采样窗口内的已完成执行；跨窗口或尚未返回的 CPU 不做比例分摊。入口 CPU 对嵌套包装去重；业务方法 CPU 包含其内部调用，不能再与入口 CPU 相加。

定时实例优先保留于有界缓存，任务对象使用弱引用，不调用业务对象的 toString 或读取业务数据。缓存最多512个任务、4096条完成事件；满时可丢弃旧证据，日志包含丢弃计数。业务方法挂钩上限256。入口栈每进程至少间隔3秒、同任务最多每分钟一次。每次快照最多查询3个热点工作线程，每线程显示近10秒 CPU 最多的3个任务实例，保留4份×512KiB滚动日志。没有记录不能据此判断没有异常。

约定的监控口径

仅 QQ 同 UID 的进程和线程；CPU 0–7 可选；QQ 在所选核心上的合计负载严格大于设置阈值才触发，默认200%；单核100%。前后台共用阈值，身份、采样、前后台或配置不满足时暂停处理。

仍只对支持的标准 FutureTask 发起协作取消，并保护整个采样窗口的任务归属。观察到任务返回才确认结束，线程池工作线程可以继续保留。EXEC 的全部核心 CPU 耗时不参与阈值计算，也不放宽取消保护。

下一次故障怎么验证

  1. 故障机安装同目录的 QQ负载监控.apk，确认模块启用且作用域含 QQ。
  2. 强行停止 QQ 后重新打开；启动精确核心采集，保留需要测试的核心和阈值。
  3. 异常出现后查看处理页的原因及展开信息，再从原导出按钮保存 TXT。建议异常出现后尽快导出，以免旧记录滚动覆盖。

故障机为 Redmi K70 Ultra（Xiaomi2407FRK8EC，日志 QQ9.2.25）；当前 ADB 手机为 Xiaomi25102RKBEC、QQ9.2.85。两台设备不同，当前装机验证不能替代故障机复现，也未证明故障业务已停止。
