QQ负载监控 v1.21

采集异常、原因变化与恢复日志 · versionCode 22

这次补了什么

  • 采集器在检测到异常、原因变化或恢复的当轮保留事件，QQ下次读取即写入原有日志，不受5秒快照节流限制。
  • 记录原始发生时间、暂停时长、QQ进程CPU时间、调度事件运行时间、校验上限与两者差值。
  • 记录丢事件增量、累计数量，以及每个核心的overrun、commit overrun、dropped events。
  • 补充采集窗口长度、进程扫描耗时、最近收到有效事件的时间、进程/线程数、缓冲区大小和计数回退身份。
  • 持续同类异常每5秒补充一次数据；异常恢复后，短暂异常的证据仍可补记。

原来的导出按钮与下载目录继续使用。核心选择、阈值、前后台规则与任务处理策略沿用；处理状态表仍不导出。

如何阅读日志

记录或原因含义
CORE_PAUSE已正常运行的采集转为无效或预热。
CORE_REASON_CHANGE暂停期间原因发生变化，立即补记。
CORE_DETAIL持续异常的定期详细数据。
CORE_RECOVER采集恢复有效；它不表示异常任务已处理。
TRACE_LOSS内核丢事件统计增加，查看lossDelta和lossPerCore。
CPU_TIME_MISMATCH进程CPU时间超过调度记录时间×1.25＋80毫秒。可能缺事件或有采集时序偏差，不等同于已确认缓冲区溢出。
PROCESS_COUNTER_ROLLBACK同一进程启动身份的CPU计数回退。
PROCESS_SET_CHANGED / WARMUP进程集合变化或采集预热；不能据此判定泄露。
CORE_STATE / CORE_GAPQQ读取端的有效性变化；或事件缓存已轮换、部分证据缺失。

procCpuNs、traceRuntimeNs、allowedNs与cpuMinusTraceNs的单位均为纳秒。compared=0表示本轮尚不能比较。
