QQ负载监控

仅 QQ · 核心可选 · 实际 CPU 时间 · 处理状态可查

当前规则

项目口径
监控对象仅 QQ 同 UID 的进程与线程；CPU0—7 任意组合，默认全选，至少一个核心。
触发阈值QQ 在所选核心上的实际 CPU 时间合计。单核满载100%，默认200%可设置；严格超过阈值才触发。
前台与后台确认QQ是否在前台；前后台共用相同阈值，首轮有效超限采样立即尝试处理。
处理结果表格保留最近100条，显示时间、线程、合计负载和实际状态。详情可展开，当前QQ会话内保留，不导出。
频率与线程数MHz 独立显示。线程数量与最后运行核心仅供参考，不作为实际核心负载的依据。

任务处理的边界

优先定位所选核心上占用最高的未保护工作任务，复核进程/线程启动时间及任务身份。任务须覆盖整个采样窗口。当前支持标准 FutureTask 的协作取消，观察到任务返回后才显示“任务已结束”；线程池工作线程可继续存在。

取消标记已经设置但任务未返回，会显示“仍在运行”。普通 Runnable、自定义取消回调和原生线程缺少专用停止接口时，显示“无法处理”或“未处理”。同一未成功目标每10秒最多重试一次。主线程、Binder、渲染、GC和模块线程受保护，不强杀QQ进程。

高占用不能单凭阈值证明泄露。故障机真实GIF/pool异常的任务停止与跨QQ子进程业务停止仍待验证。这是当前整理交付版本，不能据此宣称已解决任意线程的强制终结。

怎么安装和开启

  1. 安装 QQ负载监控.apk，在 LSPosed / ReVanced Xposed 启用，作用域勾 QQ。
  2. 强行停止 QQ 再打开，确保新版模块载入。
  3. 桌面打开“QQ负载监控”，点击“启动精确核心采集”，根据提示授权root。
  4. 长按QQ主界面右上角“+”。一起装了QQ增强时，从增强的“实验 → 线程泄露看门狗”进入。
  5. 设置页选择核心、阈值和采样间隔，保存后开启监控；概览确认精确采样有效。

手机重启后需重新启动精确采集。要求 root、tracefs 的 sched_stat_runtime 事件及已开启的内核调度统计；模块不主动修改全局调度统计开关。数据缺失、过期、丢事件或前后台未知时暂停处理。QQ主进程被系统冻结时，判定和任务控制会延迟。

面板与日志

概览看合计与趋势、真实逐核百分比、频率、热点线程；明细看QQ全核心进程CPU参考值及导出日志；处理看结果表；设置调整开关、核心、阈值和间隔。

监控日志是UTF-8，4份×512KiB，重启QQ保留。明细页可导出到手机下载目录 Download/QQWatchdog/。处理状态表不加入导出，模块不读取聊天内容。
