versionCode 23 跨进程身份复核、Handler 执行诊断、CPU 采样对齐

本次完成的三处调整

问题现在的行为
主进程读取 MSF 等子进程线程信息失败，被当作“已退出”。发送请求后由目标进程读取自己的 PID/TID 启动身份；分开报告读取失败、真实退出和身份变化。主进程仍校验请求编号、目标身份与时效。
Handler 线程事后回到消息队列等待，日志无法说明刚才执行了什么。执行时记录 Handler 消息编号、回调路线、实际业务入口、CPU 耗时与可取得的入口栈；保留最近10秒，区分正在执行但无取消接口，以及消息已返回或切换。
线程扫描耗时使进程 CPU 与调度计数的读取边界不同。扫描完成后，先后读取进程 CPU，中间固定一份调度计数及其时间。使用 CPU 时间下限校验，减少读取边界偏差导致的暂停；仍保留原完整性保护。

这些修复补齐定位和判断链路。标准 FutureTask 仍按原策略协作取消并确认实际返回；普通 Handler 消息没有已验证的业务停止接口时，仍会显示具体限制。

原约定继续执行

  • 仅统计 QQ 同 UID 进程在所选 CPU 核心上的实际运行时间；CPU0—7 可任选，至少选一个。
  • 单核满载为100%；默认合计阈值200%，可设置。严格超过阈值，在首轮有效采样立即尝试处理。
  • 确认 QQ 前后台，二者共用同一阈值；按所选核心贡献定位最忙的未保护工作线程及其任务。
  • 处理记录继续使用分组表格：完整线程名、PID/TID、QQ合计与线程自身负载、核心/阈值、前后台、结果和原因；展开查看执行与失败证据。最近100条在当前 QQ 会话内保留，不导出清单。
  • 主线程、Binder、渲染、GC 和模块线程受保护。缺失、过期、丢事件或前后台未知时暂停处理。

新状态与日志怎样看

代码或字段含义
IDENTITY_READ_FAILED目标进程无法读取身份；表格显示“身份未确认”，不能算作线程已退出。
THREAD_EXITED目标进程确认该线程目录已不存在；显示“目标已退出”，不等同于模块成功取消。
PROCESS_IDENTITY_CHANGED / THREAD_IDENTITY_CHANGED进程或线程启动身份变化，拒绝对旧目标发起取消。
HANDLER_NO_CANCEL_INTERFACE正在执行 Handler 消息，尚无已验证的取消接口。需要具体业务适配。
HANDLER_TASK_NOT_ACTIVE记录过消息执行，处理时消息已返回或切换，没有当前可取消任务。
messageWhat / callbackRoute / routeObserved消息编号、分发路线与实际业务入口是否被观测；分发被观测不代表业务方法一定已覆盖。
procCpuLowerNs / procCpuUpperNs与调度计数窗口对应的进程 CPU 时间上下限；兼容字段 procCpuNs 现在表示下限。
aligned=bracketed / cpuReadBracketNs本轮使用前后 CPU 读取夹取调度计数；读取区间单位为纳秒。

下限仍须不超过 traceRuntimeNs × 1.25 + 80,000,000ns。真实丢事件、CPU 时间下限超出此上限或计数回退，仍暂停处理；不会把缺失调度记录当作有效核心负载。

原日志与导出按钮沿用，位置仍为下载 / QQWatchdog。Handler 只记录类名、消息编号和入口信息，不读取消息 obj/data 或聊天内容。执行 CPU 是全核心诊断参考，不参与所选核心触发。
